# WorkChat Mini v2.28.0 — Research + Writing Pipeline

## Scope

This release starts the Story Companion intelligence pipeline after the v2.27 UI work. It intentionally avoids browser, Discord call-guard, notification, window/tray and resource-policy changes.

## Narrative pipeline

Narrative requests now use:

`Recall → Research Gate → Plan → Continuity Pre-check → Draft → Editor Pass → Final Continuity Check → Bookkeeping`

Ordinary brainstorming/discussion remains on the direct response path. Writer role always uses the pipeline; Companion/Editor requests use it only when the prompt looks like a writing/drafting request. Character and Worldmaster modes remain direct to avoid changing roleplay/simulation semantics unexpectedly.

## Research Gate

Research is requested only when the model decides real-world accuracy materially helps. The gate is instructed not to leak unpublished character names, secret plot details or invented project terms into search queries where a generic real-world query is sufficient.

Provider-native search is used with no new package dependency:

- OpenAI: Responses API hosted `web_search` tool.
- Gemini: Google Search grounding through `googleSearch` on `generateContent`.

If research fails or a selected model does not support search, drafting continues without research and logs the failure. Research is an enhancement, not a hard dependency.

## Research cache

Per-project cache:

`research/research-cache.json`

Each note stores:

- query;
- concise factual synthesis;
- relevance to the current draft;
- confidence;
- access timestamp;
- source title + URL.

Exact normalized queries are reused for 14 days. Cache is bounded to 80 notes. Research is never merged into Story Memory and never becomes canon automatically.

## Research UI

A `Research` item appears in the Story tools only after the active project has cached research. It opens in the existing modeless right inspector. Source URLs are rendered as clickable links. No new popup window was added.

## Writing stages

- Planner creates a private compact plan.
- Continuity pre-check verifies knowledge, location, condition, progression, inventory, relationships, timeline, world rules and open threads.
- Draft is private and is not saved to conversation/manuscript.
- Editor pass produces the user-facing streamed answer.
- Final continuity check returns structured pass/repair information.
- Concrete continuity failures can trigger a minimal repair pass; the repaired result replaces the streamed candidate before persistence/bookkeeping.
- A repaired output is checked one more time. If the final continuity stage errors or cannot return parseable verification, the polished answer is preserved but auto-bookkeeping is skipped so unverified prose cannot silently become durable Story Memory.
- Bookkeeping still runs only on a continuity-verified final response and retains the existing Proposed-vs-Confirmed rules.

## Prompt precedence

All writing stages share this order:

`Confirmed Story Canon > Project Lore/world rules > Current creator instruction > Other Story Memory > Research Notes > Model general knowledge`

Character-specific knowledge remains separate from global truth.

## Performance / safety

- no polling;
- no background search;
- no research while Story is idle;
- search only during a narrative generation that the gate marks as needing it;
- no new third-party dependency;
- research failures are non-fatal;
- cancellation propagates through all stages;
- streaming remains coalesced by the existing WPF 45 ms flush path.

## Validation state

Static validation in the packaging environment:

- XAML parse passes;
- StoryPanel XAML handlers resolve;
- no source/XAML file reaches 1000 lines;
- BUILD/AUTO-TEST batch files remain BOM-free;
- browser/Discord/notification source was not modified by this feature work.

The packaging environment does not contain the .NET SDK, so **Windows BUILD and AUTO-TEST are still required before claiming compile/runtime regression PASS**.
