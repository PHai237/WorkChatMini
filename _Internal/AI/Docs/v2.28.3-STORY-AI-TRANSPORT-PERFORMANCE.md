# v2.28.3 — Story AI Transport + Pipeline Performance

This pass targets reliability and latency without changing Story Memory schema or browser/service behavior.

## Network transport
- Gemini HTTP connections prefer IPv4 whenever DNS returns IPv4 addresses. If a host is IPv6-only, the transport falls back to the available family.
- This is scoped to the Gemini provider HttpClient. WebView2, Discord, YouTube and other WorkChat networking are unchanged.
- Connections are pooled with bounded lifetime/idle time so multiple Story stages can reuse a healthy TLS connection.

## Request mode
- Private utility stages use ordinary non-streaming `generateContent`; they do not need SSE token delivery.
- Hidden creative Draft/repair may use buffered streaming so long generations are not constrained by the short utility timeout.
- Creator-facing Chat / Editor / Continuity Review still stream where useful.
- Private utility stages have bounded stage timeouts and richer latency logs.

## Model workload routing
- Gemini utility work uses `gemini-3.5-flash-lite` for low latency: research gate, planning/constraints, structured proposals, continuity JSON and bookkeeping.
- Creative Draft / Editor / repair keep the model selected in Story Settings.
- OpenAI routing is unchanged in this pass.

## Draft pipeline
Before:
`Research Gate → Research → Plan → Continuity Pre-check → Draft → Editor → Final Check → Bookkeeping`

Now:
`Research Gate → Research → Draft Preparation (Plan + Pre-check) → Draft → Editor → Final Check → Bookkeeping`

This removes one model round trip from every Draft Scene while preserving both plan and continuity constraints.

## Capacity resilience
- 429/503 capacity errors put that Gemini model on a short in-process cooldown.
- Later stages temporarily skip a model that just reported capacity failure instead of repeatedly paying the same failure latency.
- The saved model selection is never rewritten.

## Retrieval I/O
- Chapter Markdown text is cached in memory by file path + last-write timestamp.
- Unchanged chapters are not reread from disk on every prompt.
- Editing a chapter file externally invalidates that file's cache entry automatically on the next search.
