# v2.28.5 — Memory v2 / Significant Event Ledger

Purpose: let low-effort / autonomous Story writing remember what the AI itself established without forcing the creator to manually maintain canon.

## Memory model

- **Current State** answers “what is true now?”: character abilities, inventory, knowledge, location, condition, progression, relationships, canon, lore and open threads.
- **Event Ledger** answers “what changed, when, to whom, and where was it established?”
- Final prose is the source of truth. Planning/research/private candidate ideas never enter the ledger.

Example: if Chapter 9 explicitly shows Magica learning `Starfall Severance`, bookkeeping should update `Magica.Abilities` and emit an `AbilityLearned` event. After the chapter file is saved, WorkChat stamps that event with `Chapter 9: <title>`. Later retrieval can answer both “can Magica use it?” and “when did she learn it?”.

## Significance rules

Store events only when future continuity may depend on them. Critical/Major events include death, identity/world-state change, new/lost powers, important items, secrets learned, relationship thresholds, meaningful injuries/recovery, discoveries and thread resolution. Minor is reserved for durable low-impact changes; routine movement/dialogue/decorative actions should be omitted.

## Compatibility

Schema v1 projects load safely as schema v2 with an empty event ledger. No history is fabricated from old timeline data. The next normal memory save persists schema v2.
