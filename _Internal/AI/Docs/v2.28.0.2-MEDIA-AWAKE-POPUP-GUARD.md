# WorkChat Mini v2.28.0.2 — Media Awake + Popup Guard

## Purpose

Patch on top of v2.28.0.1. No Story schema migration.

## Changes

- Service WebViews now block non-user-initiated `NewWindowRequested` popups, matching the existing Web-tab popup policy. This prevents extension/update/promotional pages from automatically hijacking the Web surface.
- Added a Windows execution-state guard while YouTube playback or Discord real-time call/audio is active.
- YouTube playback uses an injected HTML-video play/pause detector plus WebView2 audio as fallback, so muted video playback is protected too.
- Discord uses the existing WebRTC call detector plus WebView2 audio fallback.
- User-away resource logic no longer suspends YouTube while protected playback is active.
- Execution-state request is released as soon as media/call activity stops and on app exit.

## Windows behavior

While protected activity is active, WorkChat requests both system and display wakefulness. This is intended to prevent normal idle sleep/display-off; administrator-enforced lock/power policy, lid-close behavior, forced shutdown, or critical-battery actions may still override the app.

## Validation

Requires Windows BUILD + AUTO-TEST and a manual media smoke test before compile/runtime clean can be claimed.
