# WorkChat Mini v2.29.6-preview1 — Narrative Quality / Continue Story

**Base:** v2.29.5-preview22.1 (Windows Quick + Stress each 22 PASS / 0 FAIL / 0 WARN).

**Validation status of this version:** source/static audit only; Windows BUILD/Quick/Stress still required. No claim of runtime pass.

## Product behavior

- Continue Story keeps its existing autonomy (Guided/Balanced/Autonomous), Core Genres and Temporary Tags. No user-facing preference or memory schema is added.
- The *existing* draft preparation, draft and editor requests get stage-specific writing guidance. No additional AI writing stages or API calls.
- Planning favors an earned scene turn, character agency and subtext over compulsive action/cliffhangers, but neither a quiet chapter nor a surprise twist is forbidden. Creator direction and confirmed canon continue to govern the story.
- Narrative Focus can show the **two most recent uniquely numbered, committed chapter summaries** as evidence of recent story rhythm. Current canon/retcons remain authoritative. The section is lowest priority within the 2,380-character Narrative Focus budget: it may be omitted when higher-priority arcs, threads, character and location states need space.
- The existing editor pass receives conservative local hints about identical paragraphs, repeated paragraph openings, and an exactly repeated dialogue line (3+ occurrences). This is a non-blocking **advisory** only; it never edits prose by itself, blocks commit, flags a memory conflict or fabricates a canon event. The scan is capped at the same 60k-character draft excerpt sent to the editor.
- Plain routine Continue Story inputs (blank / `tiếp tục` / `viết tiếp` / `continue`, etc.) skip the **Research Gate utility API request** because no real-world fact was requested. A direction mentioning concrete conditions, e.g. `tiếp tục ở Tokyo thời Edo`, still uses the normal Research Gate and optional research flow. Draft preparation/draft/editor/continuity/bookkeeping are untouched.

## Regression additions

`StoryNarrativeCraftSelfTest.Verify()` runs within the existing `StoryLongRetrievalSelfTest` case. It checks:

1. Routine Continue Story inputs vs explicit factual directions for Research Gate routing.
2. Latest committed beat summaries vs duplicate chapter numbers and older chapters.
3. No evidence from uncommitted/dangling event rows.
4. Bounded narrative context.
5. Duplicate paragraph/dialogue hint detection and no false warning on a short quiet scene.
6. No mandatory cliffhanger guidance.

The total number of top-level self-tests remains 22.

## Optional creative smoke test (not covered by 22 mechanical tests)

On a **copy** of an existing story or a disposable story:

- Choose `Balanced`, leave Continue Story input blank for a scene, then use `tiếp tục` once. Check whether the narrative moves through consequences rather than repeating a climax.
- Enter a brief director prompt for a low-conflict conversation; verify that the characters speak naturally, with motive/subtext and no forced attack or generic cliffhanger.
- Switch between two different temporary tags; confirm each influences only the current scene's tone without changing Core Genres.
- Give a specific factual direction (real historical/technical detail) and verify the Research Gate is *not* bypassed.
- If testing rollback, switch between existing branches and verify the new recent-beat note does not pull information from an inactive branch.

Qualitative writing quality requires these on-device generation checks; passing the automated suite alone cannot prove superior prose.
