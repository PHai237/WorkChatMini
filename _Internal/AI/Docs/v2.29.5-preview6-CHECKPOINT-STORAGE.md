# WorkChat Mini v2.29.5-preview6 — Checkpoint Storage Hardening

**Base:** `WorkChatMini-source-v2.29.5-preview5.zip`  
**Prior Windows-validated baseline:** v2.29.5-preview2.1 — Quick and Stress both 22 PASS / 0 FAIL / 0 WARN.  
**Validation status for preview6:** static/package checks only. **Windows BUILD, Quick and Stress not yet run.**

## Changes

1. **Compressed checkpoint snapshots, version 2.** New checkpoints store `memory.json.gz` and `conversation.json.gz` rather than repeated uncompressed JSON. Each compressed payload has a SHA-256 of the *uncompressed UTF-8 JSON* in `checkpoint.json`. The manifest remains the last file written. Compression uses `CompressionLevel.Fastest` to avoid a heavy CPU budget.
2. **Backwards compatibility.** The absence of the `SnapshotFormat` field defaults to version 1 and loads existing `memory.json` / `conversation.json` unchanged. No eager migration or deletion of old checkpoint data is performed.
3. **Integrity validation.** Before a restore, both compressed snapshots are decompressed and SHA-256 checked, structurally deserialized, and all chapter objects checked. A corrupt or missing checkpoint refuses to restore rather than silently replacing the active story. Decompressed JSON is limited to 128 Mi characters per file to avoid excessive accidental memory allocation.
4. **Streamed chapter hashing.** SHA-256 checks of prose files and immutable objects now use asynchronous streams rather than loading each whole chapter into a `byte[]`. A newly captured chapter object is checked again after copying, so an outside edit during capture cannot publish a mismatched object.
5. **Safe cleanup of duplicate chapters.** Once a restore completes and its journal is removed, the temporary *whole-directory* copy in `branches/history/<transaction>-previous-chapters` and staging directory are deleted. The recoverable **safety checkpoint and content-addressed objects remain intact**. No garbage collection of chapter blobs, archives, old orphan folders or branch heads is performed.
6. **Restore gating.** Rollback refuses to start while a commit/restore journal or an unfinished branch switch exists. During restore, both target and distinct safety checkpoints are validated before replacing live chapters.
7. **Self-test expansion within existing 22 cases.** Covers compressed snapshot creation/reading, actual compression on a repetitive long conversation, rejection of damaged gzip content, plaintext format-v1 compatibility with missing snapshot-format fields, and cleanup of duplicate chapter directories after completed rollback. No additional top-level test cases.
8. **Version consistency.** Updated csproj informational/file/assembly version, BUILD/AUTO-TEST banners, and `_Internal/VERSION.txt` to preview6.

## Deliberate limitations

- Still **not** Git-style branch merge. No automatic deletion of archived branches, chapter objects, old checkpoints, or historical backup folders that predate this update. Automatic reference-count-based garbage collection is intentionally deferred to avoid deleting content relied on by inactive branches.
- A checkpoint still hashes each chapter on capture to detect out-of-app edits. This design prioritizes correctness and bounded memory over making checkpoint creation constant-time for very long manuscripts.
- The new GZip files are readable by preview6 and later. Reopening a story containing **new preview6 checkpoints in older preview5 binaries is not supported** for those particular checkpoints; existing older checkpoint files and live story data are not converted.
- Crash recovery remains journal-based. Windows end-to-end BUILD/self-test and live UI behaviour require validation at the next agreed integration milestone, not after every preview.
- No WebView, Discord, YouTube, adblock, notification policy, icon or browser-shell logic was intentionally changed.
