# WorkChat Mini v2.29.5-preview8 — Deep Checkpoint Integrity

**Base:** `WorkChatMini-source-v2.29.5-preview7.1.zip` (Windows-validated: Quick 22/0/0, Stress 22/0/0, 2026-10-09).  
**Preview8 status:** Source integration / static checks only. **Not Windows BUILD or runtime validated**.

## Added

1. **Opt-in deep integrity scan:** `Memory → Story Branches / Versions → STORAGE HEALTH → Verify checkpoint integrity (read-only)`. Unlike fast metadata inventory, this validates checkpoint manifests, decompresses Memory and Conversation snapshots, parses both JSON payloads, checks chapter references, and hashes actual referenced chapter objects.
2. **Hash once per unique chapter object per scan:** Many checkpoints share content-addressed chapter objects; the scanner caches hash outcomes to avoid repeatedly reading the same large chapters. Runs off the WPF UI thread.
3. **Legacy support:** Reads pre-preview6 plaintext snapshots without changing them. Legacy snapshots cannot be cryptographically authenticated because they contain no original checksum; the UI explicitly discloses this.
4. **Branch head validation:** Checks active/archived branch heads resolve to a fully verifiable checkpoint. A pending commit/restore/branch switch marks the report as needing another scan after recovery.
5. **Bounded diagnostics:** Displays only up to eight individual problems and a total of remaining issues. Does **not** repair or delete files, including orphaned objects, temporary restore directories, or corrupted snapshots.
6. **Concurrency UI guard:** Story commit, normal chat generation, proposal apply, rollback and branch operations are blocked while the storage scan is running. The scan is read-only and never auto-runs on startup.
7. **Existing Story self-test extension:** Adds test cases using disposable fixtures: valid checkpoint verification, corrupted compressed snapshot, corrupted immutable chapter object, and re-verification after restoring test-only files. Top-level test count remains **22**.
8. **Version identification:** `2.29.5-preview8`, Windows assembly/file version `2.29.5.10`.

## Boundaries

- No background scan, automatic cleanup, garbage collection, branch merge, or content migration.
- Does not verify *unreferenced* objects; fast storage inventory continues to list such objects conservatively. No object is declared safe to delete.
- The deep scan checks a point-in-time view; avoid editing story files externally while it runs.
- Verification may take longer for stories with many checkpoints; unique chapter hashing is shared across checkpoints but each snapshot still needs decompression and parsing.
- No change to Memory schema v6, AI writer pipeline, browser, Discord guard, AdBlock, notifications, or icons.
