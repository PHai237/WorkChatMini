# WorkChat Mini v2.29.5-preview2 — Checkpoints and recoverable rollback

Base: v2.29.5-preview1 (`alternate-drafts-isolation`), built on v2.29.4 validated baseline.

## Scope

- **Before every successful generated chapter commit**, a checkpoint is created from the full Story Memory v6 document and the conversation before committing the new chapter.
- Chapters are referenced by SHA-256 content-addressed immutable files under `branches/objects`; repeated checkpoints do not duplicate unchanged chapter prose.
- Chapter metadata stores `CheckpointId` for the corresponding before-commit restore point.
- A committed message with checkpoint now offers **Return before this chapter**, followed by inline confirmation.
- Memory → Overview → **Story Versions / Rollback** lists recent checkpoints and offers explicit restore / redo of the safety snapshot.
- Restore validates the target memory/conversation/manifest and SHA-256 hashes BEFORE changing active files. It captures the current active state as a separate safety checkpoint.
- Restore replaces the complete active chapter set, memory, and conversation, preserving the prior live chapter directory in `branches/history/` as additional recovery material.
- An on-disk `pending-restore.json` journal allows an interrupted rollback to finish before the story is loaded again. A failed recovery blocks generation for that story.
- Discards chapter-text cache and local chapter index after restore, preventing reuse of stale content from another version with an identical filename.
- Kept existing preview1 uncommitted draft isolation, alternate versions and sibling commit exclusivity.
- Extended **Story memory persistence and retrieval** (existing self-test case) with checkpoint → rollback → retrieval isolation → safety restore roundtrip. Remains 22 test cases.
- Version metadata changed to 2.29.5-preview2. Self-test header now prints the actual informational build version, instead of the 2.29.4 assembly version inherited by preview1.

## Limitations / safety

- This is **preview2**, not a finished multi-branch timeline editor or compact reversible-delta engine.
- Restore snapshots cover structured story memory, conversation, and chapter prose. Story metadata/preferences and research cache are intentionally outside this boundary. Research does not become canon.
- Snapshotting the complete memory and conversation JSON per chapter has a disk cost; chapter prose is deduplicated. A restore additionally archives the previously active chapter folder to avoid deleting untracked files.
- Old chapters created before preview2 do not automatically gain past checkpoints.
- An unexpected process termination *during* the chapter commit transaction (as distinct from restore) is not yet covered by the restore journal; this requires next-phase commit journaling and recovery testing.
- No Windows/.NET SDK available in the authoring runtime: **Windows BUILD, Quick and Stress still must be run**. Do not treat this preview as validated.

## Windows verification

1. Extract into a new directory and run `AUTO-TEST.bat` (build, Quick and Stress in sequence).
2. Reports should begin with `WorkChat Mini 2.29.5-preview2-checkpoint-rollback Self Test`, both showing `22 PASS / 0 FAIL / 0 WARN`.
3. With a test story, create and commit chapter A; commit chapter B; click Return before this chapter on B; confirm that only A remains active and that B's canon/prose does not reappear in retrieval.
4. In Story Memory → Story Versions / Rollback, choose the automatically preserved safety snapshot and restore B.
5. Keep a backup of important personal stories while using this preview build.
