# WorkChat Mini v2.29.5-preview15 — Character Knowledge / POV Boundary

**Base:** `v2.29.5-preview14` (source). The last Windows-tested baseline remains `v2.29.5-preview7.1` (Quick and Stress: 22 PASS / 0 FAIL / 0 WARN).

## Motivation

A long-story writing system needs to distinguish **world truth (what the author can know)** from **character knowledge (what a character has witnessed, learned, or believes)**. Canon, Event Ledger, causal trace, retrieved chapters and Knowledge Graph can describe secrets that no specific character has yet learned. Those results remain useful to the author but must not automatically become character thoughts, dialogue, or motivations.

## Changes

1. **`StoryKnowledgeBoundary.cs` (new):** compact, deterministic, read-only guidance near the beginning of writer memory context. Draws only on the active Story Memory (no new API calls).
2. **Explicit POV override:** recognises narrow creator directives such as `POV: Luna`, `point of view of Luna`, or `góc nhìn của Luna`. A unique canonical name or unique alias is needed; a shared nickname cannot silently become a POV.
3. **Conservative continuation POV:** if Continue Story doesn't request a POV, the assistant can use the last *committed chapter's* recorded POV; it does not fall back to an older chapter's POV. Normal chat/continuity queries don't silently inherit a POV.
4. **Character knowledge summaries:** bounded snippets for the POV and a few relevant or physically present characters. A missing structured knowledge record is labelled **unverified**, not proof the character is ignorant. Character beliefs need not be identical to world truth.
5. **Secret labeling:** `StoryCharacterMemory.Secrets` is labelled as *author-only secret notes* in the character context, not proof that any character knows them.
6. **Writer, bookkeeping, and final continuity rules:** reinforce the author-versus-character separation; bookkeeping must not propagate narrator-only secrets to each character. The final checker is instructed not to flag a supposed knowledge leak based only on an absent structured record.
7. **Self-test additions:** extends `StoryLongRetrievalSelfTest` (still **22 top-level cases**) with committed POV, creator POV override, shared nickname, old-scene rejection, empty knowledge, and preservation of world canon for the author.
8. **Version labels:** `2.29.5-preview15` consistently in csproj, batch scripts, and `_Internal/VERSION.txt` (assembly/file version `2.29.5.17`).

## Compatibility / scope

- No Story Memory schema change (still v6); no data migration, no auto-delete.
- No changes to branch storage, checkpoint or rollback transaction semantics.
- No changes to WebView2, browser, Discord Call Guard, AdBlock, notifications or AI provider/network routing.
- No new dependency, embedding model, or API calls.
- This is **prompt-context hygiene and conservative POV identification**, not deterministic proof that every generated sentence preserves epistemic continuity. The continuity stage remains the final safeguard.
