# WorkChat Mini v2.25 — AI Foundation

This version introduces the first usable Story Companion foundation while keeping the long-term architecture in `WorkChat_AI_Story_Companion_Blueprint.md` intact.

## Included now
- Story Companion service immediately to the right of Web.
- Approved pixel book + quill icon.
- Native WPF chat surface; no extra WebView is kept alive for AI.
- Multiple local story projects.
- Core Genre checklist plus Temporary Tags for the current scene/chapter/arc.
- Working roles: Companion, Writer, Editor, Worldmaster, Character.
- Gemini API and OpenAI API provider abstraction.
- Provider/model can be changed without moving story projects.
- API keys protected for the current Windows user with DPAPI and never stored in normal `settings.json`.
- Streaming text with cancellation.
- Coalesced stream rendering to avoid one Dispatcher job per token.
- Persistent project conversations.
- Context budget: recent relevant chat foundation only (v2.25); full layered Story Memory comes next.

## Not implemented yet by design
- Canon database / Story Bible / character knowledge graph.
- Chapter/arc memory and bookkeeping approval.
- SQLite FTS retrieval.
- Web Research Gate.
- Planner / continuity checker / editor pipeline.

Those belong to v2.26+ so the AI shell/provider layer can be compiled and validated independently first.

## Local storage
Runtime story data is stored under the normal WorkChat local data directory in `AI/Projects` and encrypted provider credentials in `AI/Credentials`.

The project files are local. When the user asks the AI to generate a response, the selected context required for that request is sent to the configured model provider.

## Build validation target
`AUTO-TEST.bat` should report **19 PASS / 0 FAIL / 0 WARN** in both Quick and Stress modes. The additional case validates Story project persistence, encrypted credential round-trip, and Story surface switching without treating Story as a WebView.
