# v2.28.3.2 — Gemini Transport Initialization Hardening

## Fix

- Removed eager static `HttpClient` construction from `GeminiStoryProvider`.
- Gemini transport is now created lazily on first use.
- IPv4-preferred `SocketsHttpHandler` remains the primary path.
- If the managed VPN/proxy stack rejects the preferred handler during construction, WorkChat falls back to a platform `SocketsHttpHandler`.
- If that fallback also cannot be constructed, WorkChat uses a default `HttpClient` rather than poisoning the Gemini provider type.
- Full initialization exceptions are written to the Story AI log.

## Why

`v2.28.3.1` created the optimized Gemini transport in a static field initializer. A construction-time exception therefore became a `TypeInitializationException` and made every Gemini request fail for the rest of the process. Transport optimization is now fail-open and cannot disable the provider.

Windows BUILD/runtime verification is still required before claiming compile-clean/regression-clean.
