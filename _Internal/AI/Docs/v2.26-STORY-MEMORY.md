# v2.26 — Story Memory

This release adds the first persistent long-form story memory layer.

Implemented:
- full narrative chapter files under each project;
- structured memory for canon, characters, character knowledge, relationships, timeline, threads and lore;
- relevance-based memory retrieval before generation;
- full-text search over stored old chapter Markdown files;
- a separate AI bookkeeping pass after substantial narrative output;
- Confirmed vs Proposed memory;
- Memory inspector and auto-bookkeeping toggle;
- provider-independent storage;
- self-test for persistence and early-detail retrieval.

Current storage intentionally uses Markdown + JSON to avoid adding a new database dependency during this stabilization step. Storage is abstracted so SQLite/FTS can be introduced later without rewriting the Story UI or provider layer.
