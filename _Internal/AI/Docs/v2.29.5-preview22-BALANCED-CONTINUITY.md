# WorkChat Mini v2.29.5-preview22 — Continue Story Balanced Continuity Batch

**Based on:** `WorkChatMini-source-v2.29.5-preview21.zip` (full source).

**Last Windows-validated baseline:** `v2.29.5-preview15.1`, Quick and Stress each `22 PASS / 0 FAIL / 0 WARN`.

**This release:** Integrated source changes, static audit only. **No Windows BUILD, Quick or Stress has yet been run for preview22.**

## Purpose

Preserve the quality of Continue Story with Flash/Flash-Lite while preventing the context from becoming a huge checklist. Improve narrative consistency without making Gemini follow a rigid plot, adding a new memory database, or increasing provider calls.

## Implementation

1. **Narrative Focus budget enforcement and priority fairness.** Rework `StoryNarrativeFocus.Build` to stay **within 2,380 characters**, which fits its 2,400-character writer allowance. The order is: main arc, open thread, setup/payoff, active character arc, then separate bounded choices, priorities and consequences; a committed scene may follow. Each section gets a fixed quota, and sections/lines are omitted whole instead of presenting a partially cut fact as truth. This fixes a design issue where long character summaries could crowd out the main plot or be truncated arbitrarily.
2. **Character Priority & Vow Evidence (new derived module).** `StoryCharacterPriorityFocus` joins current goals with significant past decisions and in-story promise events already in Event Ledger. It is **read-only and branch-local**. Only `Confirmed` events with on-page evidence, uniquely resolved actors, non-colliding event IDs and committed chapter provenance are eligible. Vows are keyed by their **exact target**: a kept/broken promise about one target cannot hide a different promise without a recorded outcome. No promise is called "certainly binding" just because its resolution was not recorded. No speculative goal conflict is declared.
3. **Tighter causal provenance for decisions.** `StoryCharacterMotivationFocus` now rejects event IDs duplicated anywhere in the ledger (including Proposed records), and rejects a causal link dated earlier than the linked events. A causal edge still needs explicit evidence, a committed chapter and verified endpoints. Historical proximity never counts as causality.
4. **Bookkeeping conflicts become reviewable risks.** `StoryCharacterMotivationGuard` marks `contradictory-vow-outcomes` when the same uniquely identified character has both `PromiseKept` and `PromiseBroken` for the same target in one confirmed update. It marks `goal-readded-in-same-update` when `Goals` and `RemovedGoals` repeat the same target. These are **Risk warnings only**, not a forced canon retcon, discarded prose, or hard conflict.
5. **Deeper regression coverage under the existing 22 cases.** Added `StoryCharacterPrioritySelfTest.Verify()` into the existing Story memory/retrieval case, with assertions for completed/unresolved vows with distinct targets, shared aliases, Proposed events, uncommitted branch chapters, ID collisions, self-consistency warnings, overloaded arc/thread contexts, section budget and branch-local isolation. Strengthened the older motivation self-test for premature causal links and Proposed ID collisions.

## Compatibility & unchanged behavior

- **Story Memory schema remains v6**. No migration; no new persisted fields or files for user stories.
- **No browser, Discord Call Guard, WebView2, notification, AdBlock, provider, genre/tag, branch/rollback or checkpoint format changes.**
- **No new dependencies, AI request stages or network requests.** All new work happens locally from existing memory.
- Continue Story remains autonomous within the selected Guided/Balanced/Autonomous setting; the new guidance never forces a character to repeat an earlier choice.
- No automatic cleanup, deletion or rewriting of user stories.

## What needs Windows validation

When you decide to run the integration test:

1. Extract the **complete** ZIP to the source folder (keep the original story data under LocalAppData).
2. Run `BUILD.bat`. The banner must say `v2.29.5-preview22`.
3. Run `AUTO-TEST.bat`, Quick and Stress. Goal: `22 PASS / 0 FAIL / 0 WARN` for each.
4. If a case fails, send the first failing case and the corresponding self-test log. Do **not** weaken assertions to force green.

**Static audit is not a substitute for a WPF compile or runtime test.** `preview15.1` remains the last Windows-validated baseline until the new reports are clean.
