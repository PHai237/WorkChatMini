# WorkChat Mini v2.28.1 — Story Actions v1

## Goal
Make the five Story Companion actions behave as distinct workflows instead of prompt shortcuts.

## Action routing

### Chat
Normal conversation. If the creator types a clear narrative-writing request without selecting an action, the legacy narrative signal classifier may still invoke the writing pipeline for convenience. Role does not decide routing.

### Draft Scene
Recall → Research Gate → Plan → Continuity Pre-check → Draft → Editor → Final Continuity → optional repair → Bookkeeping.
Only the final verified result is eligible for durable memory/bookkeeping.

### Plan Chapter
Recall → Research Gate → private plan → continuity constraints → creator-facing chapter plan.
No narrative draft and no bookkeeping.

### Check Continuity
Recall → direct continuity review.
Read-only. No draft, no repair, no bookkeeping, no memory mutation.

### Build Character
Recall → structured character/cast-fit proposal.
Nothing is written to Story Memory until the creator clicks **Add to Story**. Accepted relationship patches are applied with the character.

### Expand Lore
Recall → optional Research Gate → lore proposal → continuity check.
Nothing is written automatically. **Save as Proposed** stores the returned lore with Proposed status; Memory review can later approve/discard it.

## UX
Selecting an explicit action shows a compact action chip above the composer and changes the composer hint. Clicking the same action again or the × in the chip returns to normal Chat. The action resets to Chat after Send so later messages are not accidentally routed into the previous workflow.

Assistant message badges show which explicit action produced the response. Proposal action state is persisted in `conversation.json` through optional `StoryMessage` metadata fields, preserving backward compatibility with old conversations.

## Safety / compatibility
- No Story Memory schema migration.
- No browser/Discord/notification implementation changes.
- Existing projects and old conversation JSON remain loadable because new message fields have defaults.
- Research remains lower priority than canon/lore.
- Role controls collaboration guidance only; it no longer chooses the workflow.
