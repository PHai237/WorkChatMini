# WorkChat Mini v2.29.5-preview5 — Branch Archive & Read-only Comparison

Based directly on **preview4**. Last Windows-validated baseline remains **preview2.1** (Quick and Stress 22 PASS / 0 FAIL / 0 WARN). This preview is **NOT** Windows BUILD/runtime validated.

## Implemented

1. **Archive inactive branches safely.** In Story Memory → Story Branches / Versions, the inactive branch has an `Archive` action with inline confirmation. Archiving moves only its name/head pointer from `Branches` to `ArchivedBranches` in `branch-index.json`. No chapter, memory checkpoint or object is deleted. Archiving the currently active branch is rejected.
2. **Restore archived branches.** Archived branches are listed under a collapsible Archived Branches section. Restoring preserves the archived branch's ID and head checkpoint. If the original name is already in use, a new unique `(restored)` suffix is assigned. Restore does *not* switch the active branch. Active limit remains 20; archived limit is 100.
3. **Read-only Compare** for inactive branches. Displays chapter counts, cast/promise/causal counts, and bounded examples of different chapter titles, confirmed canon facts, characters, open promises and causal links. Compares the in-memory active state against a fully validated target checkpoint. No merge or mutation. Chapter-title equivalence is *not* presented as a prose hash comparison.
4. **Safety checks**: reject create/rename/archive/restore-archived while checkpoint/commit recovery is pending. Validate archive metadata, unique IDs across active+archived and archival timestamps.
5. Extend existing Story branch self-test to check comparison, inactive archiving, active-branch protection, archived branch restoration and Main/B isolation after switching back. Still **22 top-level self-tests**.
6. Update `BUILD.bat`, `AUTO-TEST.bat` banners and assembly informational version so the next Windows reports can be traced correctly.

## Compatibility and deliberate limits

- Existing `branch-index.json` version 1 remains compatible: `ArchivedBranches` defaults to an empty collection for old saves.
- Checkpoints and content-addressed chapter blobs are retained even when branches are archived. **No garbage collection or permanent deletion** in this preview.
- Not a Git-style merge engine, and not a text-level diff. No automatic inference that canon from two branches can be merged safely.
- Branching remains per story; the global WebView/Discord/adblock/notification services are untouched.
- No new dependency, schema v6 stays the same, source files kept below 1000 lines.
- Static inspection only. Windows compiler errors/runtime behavior, especially the WPF UI, must be checked at a later integrated milestone as agreed.
