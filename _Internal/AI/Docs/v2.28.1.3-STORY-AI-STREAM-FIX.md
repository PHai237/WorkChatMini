# v2.28.1.3 — Story AI streaming hang fix

## Fixed

- Removed synchronous `StreamReader.EndOfStream` polling from Gemini and OpenAI SSE loops.
- Provider streaming continuations now stay off the WPF UI synchronization context via `ConfigureAwait(false)`.
- Added a 45-second SSE inactivity timeout so a dead connection cannot wait forever.
- Added provider diagnostics for request start, response headers, first text chunk, and stream completion.
- Empty completed streams now surface a provider error instead of leaving a permanently blank assistant bubble.

## Why

`StreamReader.EndOfStream` can synchronously wait for more network data. The old provider loop could resume on the WPF UI thread and block it before queued streaming text was flushed, producing a blank AI bubble and potentially `Not Responding` even though response chunks had already arrived.

## Scope

This patch changes Story AI provider streaming only. Browser, Discord guard, notification policy, Story Memory schema, and Story Action semantics are unchanged.
