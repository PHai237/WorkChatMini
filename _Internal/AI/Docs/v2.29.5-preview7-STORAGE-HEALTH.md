# WorkChat Mini v2.29.5-preview7 — Storage Visibility & History Navigation

**Base:** `WorkChatMini-source-v2.29.5-preview6.zip`  
**Last Windows-validated baseline:** `v2.29.5-preview2.1` — Quick/Stress each 22 PASS / 0 FAIL / 0 WARN.  
**preview3–preview7:** source/static checks only; Windows BUILD/Quick/Stress not yet completed.

## Changes

1. **Story Storage Health — read-only.** In `Memory → Story Branches / Versions`, click **Analyze storage (read-only)**. Runs off the WPF UI thread and reports metadata inventory for complete/incomplete checkpoints, active/archived branches, content-addressed chapter objects, referenced/missing objects, temporary restore folders and live chapter disk usage.
2. **Conservative reference reporting.** If any checkpoint is incomplete, a branch head is unresolved, a referenced object is missing, an index cannot be read, or a transaction is pending, the UI suppresses the unreferenced-space estimate. Even on a clean scan, the metric means only “not referenced by a readable manifest”, **NOT safe to delete**. Nothing is deleted or migrated.
3. **Restore-point history pagination.** Previously only eight recent restore points were visible. The UI now offers **Older restore points / Newer restore points**, showing eight per page. Archive/switch checkpoints remain excluded from the normal restore-point list. The store adds an optional `skip` argument to the existing `ListRecent` API without changing old callers.
4. **Safe metadata scan.** The audit only inspects local file metadata/manifests and sizes; it does not read the full manuscripts into memory or compute full SHA-256 for every chapter. It does not traverse directory reparse points when measuring recursively. A UI note explicitly states it is *not* a full integrity verification.
5. **Regression coverage.** The existing Story self-test case now includes disposable fixtures for unreferenced chapter blobs, incomplete checkpoints and staging leftovers; it checks conservative reporting and that the scan never removes these files. Total number of top-level self-tests remains 22.
6. **Version metadata.** Updated project, scripts and version file to preview7.

## Deliberate limitations

- No deletion, pruning, garbage collection or automatic repair of checkpoint objects, archived branches or old restore directories. This first delivers an observable inventory before planning any reclaim operation.
- An intact manifest and snapshot files can still contain corrupted payload bytes. This fast audit is a **metadata** scan, not a replacement for restore-time checksum and content validation.
- Restore point list paging still reads the checkpoint manifests to sort by creation time. Future indexing is only warranted if real projects show unacceptable UI latency.
- Legacy plaintext snapshots and existing preview6 compressed snapshots are preserved unchanged. New code does not alter memory schema, chapter format or branch index layout.
- Browser shell, AdBlock, Discord, notifications, resource management and icons were not intentionally modified.
